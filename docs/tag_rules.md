# タグ — ルールベース意味レイヤー (M3 / issue #4)

`sagasu tag` は LLM を使わずに、ファイルについて**すでに分かっていること**だけから
`namespace:value` 形式のタグを機械生成する。design.md §6 の実装。

- **決定的**: 同じファイルには常に同じタグ。再索引でタグは揺れない
- **オフライン**: ネットワークもモデル推論も使わない
- **説明可能**: どのタグがどの生成源から来たかを `sagasu tags --file` で確認できる

```
sagasu index <root> --db index.db     # メタデータ索引
sagasu tag --db index.db --read-magic # タグ生成
sagasu tags --db index.db             # 名前空間の一覧(ファセットの最上位)
sagasu tags kind:image --db index.db  # そのタグを持つファイル
```

## 1. 組み込みの生成源

| 名前空間 | 生成源 | 例 |
|---|---|---|
| `format:` | マジックバイト(なければ拡張子) | `format:pdf` `format:zip` `format:text` |
| `ext:` | 拡張子(別名を畳む) | `ext:jpg`(`.jpeg` も同じ) |
| `kind:` | 形式の粗い分類 | `kind:document` `kind:image` `kind:code` |
| `path:` | ディレクトリ構成要素とその分割トークン | `path:invoices` `path:acme-corp` `path:acme` |
| `date:` | 名前に含まれる日付パターン | `date:2024` `date:2024-03` |
| `version:` | ファイル名の版数マーカー | `version:v2` `version:final` `version:copy` |
| `pattern:` | 命名規則 | `pattern:screenshot` `pattern:camera` `pattern:backup` |
| `anomaly:` | 生成源どうしの矛盾 | `anomaly:format-mismatch` |

### format と magic バイト

`format:` はまず**中身の先頭バイト**から決まり、それが取れないときだけ拡張子から決まる。
schema v0 の `files.magic`(先頭 512 バイト)がその入力で、この列は `sagasu hash`
が埋める。ハッシュを走らせていない索引では `sagasu tag --read-magic` が
先頭 512 バイトだけを読んで同じ列を埋める(ファイル全体は読まないので `hash` より
桁違いに速い)。

どちらも走らせていない場合、`format:` は拡張子の言い値になる。その状態は
`sagasu tag` の出力の `magic bytes : ... missing` 行で必ず見える(実測では
`--read-magic` の有無で `format:` の付与率が 76.4% → 99.9% に変わる)。

`anomaly:format-mismatch` は「拡張子がバイナリ形式を主張しているのに、先頭バイトが
別の形式だった」ときにだけ付く。テキスト拡張子については判定しない —
Shift_JIS の `.txt` が「テキストとして sniff できない」のは
本文抽出の未対応(`crate::text`)であってファイルの誤ラベルではないため。

### 日付

日付は**極大な数字の連なり**からのみ取る。`20240315` は日付だが `1234567890` は
日付ではない。日(`DD`)は捨てて `date:2024` と `date:2024-03` の 2 段だけを出す —
1 日 1 バケツのファセット軸は辿れないし、人が覚えているのは月までだから。

### path トークン

`path:` はディレクトリ名からのみ作られる。**ファイル名の語はタグにしない**:
ファイル名は `sagasu find` と全文索引ですでに引けるが、ディレクトリ名は
他のどこからも引けないため。ファイル名からは日付・版数・命名パターンという
「解釈」だけを取る。

ディレクトリは末端から最大 12 階層、1ファイルあたりのタグ総数は 64 が上限。

上限に当たったとき、**何を捨てるかは優先順位で決まる**。捨てる順は
「他では復元できない情報」の逆順:

1. ユーザー定義ルールのタグ(人が書き下した知識。他のどこからも作れない)
2. その他の非構造タグ(`date:` / `version:` / `pattern:` / `anomaly:`)
3. `format:` / `ext:` / `kind:`(1ファイル1個ずつなので枠を食わない)
4. `path:`(深さに比例して増える唯一の軸で、かつ `sagasu find` で代替できる)

同順位内は辞書順なので、全体としては決定的な全順序になる。
辞書順でそのまま truncate していた頃は `path:` が枠を食い潰し、
`sagasu tags project:client-work` が `hits: 0` を返すという
「一致するファイルがあるのに 0 件と断言する」偽陰性が起きていた。

`sagasu tag` は上限に当たったファイル数・捨てたタグ数・その名前空間別内訳を
報告し、`sagasu tags --file` は捨てられたタグを名前ごと列挙する。

## 2. ユーザー定義ルール

組み込みの生成源はパスに**書いてあること**しか見えない。`clients/acme/**` が
請求対象の案件だとか、`**/keiri/**` が経理部門のものだといった知識は利用者側にある。
それを宣言的に書き下すのがルールファイル。

形式は TOML(`bench/configs/*.toml` と同じ。設定言語は 1 つで足りる)。

```toml
# sagasu-tags.toml

# --- 案件 ---------------------------------------------------------------
[[rule]]
name = "顧客案件"                       # 任意。エラーメッセージに出る
path = "clients/**"                     # ルート相対・'/' 区切りのパスに対する glob
tags = ["project:client-work"]

[[rule]]
name = "acme の案件"
path = "clients/acme/**"
tags = ["client:acme", "billing:billable"]

# --- 作成者(埋め込みメタデータの代わり) --------------------------------
[[rule]]
path = "**/masuda/**"
tags = ["author:masuda"]

# --- 部門 ---------------------------------------------------------------
[[rule]]
name = "経理の Office 文書"
path = "**/keiri/**"
ext  = ["docx", "xlsx", "pdf"]          # 拡張子リスト(先頭のドットなし)
tags = ["dept:accounting", "retention:7y"]

# --- アプリケーション ----------------------------------------------------
[[rule]]
file = "*.psd"                          # ファイル名だけに対する glob
tags = ["app:photoshop"]

# --- 契約書 --------------------------------------------------------------
[[rule]]
name = "契約書"
path = "**/契約/**"
tags = ["doc-type:contract", "confidential:yes"]
```

`sagasu tag --rules sagasu-tags.toml --db index.db` で適用する。
`--rules` を省略した場合はカレントディレクトリの `sagasu-tags.toml` を探し、
**見つかっても見つからなくても、どちらだったかを 1 行目に出す**。

### 2-1. マッチの規則

| キー | 意味 | 省略時 |
|---|---|---|
| `name` | 診断用のラベル | `rule #N` |
| `path` | ルート相対パス(`/` 区切り)に対する glob | 条件にしない |
| `file` | ファイル名だけに対する glob | 条件にしない |
| `ext` | 拡張子の完全一致リスト(ドットなし) | 条件にしない |
| `tags` | 付けるタグ(`namespace:value` の配列) | **必須** |

- 1つのルール内の条件は **AND**。`path` と `ext` を両方書けば両方満たす必要がある
- ルール間は**順不同**。ファイルはマッチした全ルールのタグの**和集合**を受け取る。
  したがって結果はルールの記述順に依存しない(決定性の要件そのもの)
- glob は `*`(`/` を越えない)、`**`(部分木)、`?`、`{a,b}`、`[a-z]` をサポート
- マッチは**大文字小文字を区別しない**。パス区切りは常に `/` に正規化される。
  同じルールファイルが Windows と Linux で同じタグを出すため

### 2-2. 黙って効かないルールを作らせない

以下はすべて**読み込み時のエラー**で、該当ルールの名前とともに報告される:

| 書き間違い | 何が起きるか |
|---|---|
| `tag = [...]`(`tags` の綴り間違い) | 未知のキーとしてエラー。「読み込めたが何もしないルール」にはならない |
| 条件が 1 つもないルール | エラー。全ファイルにタグが付く事故を防ぐ(本当に全件なら `path = "**"` と書く) |
| `tags = []` | エラー(何もしないルール) |
| `tags = ["namespace無し"]` | エラー。タグは `namespace:value` 形式でなければならない |
| 壊れた glob | エラー |

### 2-3. タグの正規化

名前空間と値は**両方とも小文字化**される。`author:Masuda` と `author:masuda` が
別のタグになると、ファセットのすべての件数が二分され、しかも外からは気づけない。
名前空間は ASCII の `[a-z0-9_-]` のみ。値は空白や日本語を含んでよく、128 文字まで。

## 3. 結果を見る

```
sagasu tags                        # 名前空間の一覧 + 全体の上位タグ
sagasu tags kind:                  # kind 名前空間の値と件数
sagasu tags kind:image date:2024   # 両方を持つファイル(AND)
sagasu tags --file ./report.xlsx   # 1ファイルのタグを説明する
```

`--file` は**格納済みのタグ**と**いま計算し直したタグ**を並べて出す。
差があれば、格納されたタグ層がルールやエンジンより古いということ。

タグ層の鮮度は `sagasu tags` と `sagasu status` の両方が報告する。
索引を再走査してタグを再生成していなければ「N 世代遅れ」と表示される —
タグで絞り込んだ答えから新しいファイルが黙って抜け落ちるのが、
この設計で最も避けたい失敗だから。

## 4. 実測(タグ付与率)

計測日 2026-08-07、release ビルド、Linux / ext4。

| コーパス | ファイル数 | 1つ以上のタグ | `format:` | `path:` | 構造タグ以外 | 所要 |
|---|---|---|---|---|---|---|
| `/usr`(OS ツリー、`--read-magic` あり) | 63,901 | 100.0% | 99.9% | 100.0% | 2.0% | 3.65s |
| `/usr`(同上・magic なし) | 63,901 | 100.0% | 76.4% | 100.0% | 2.0% | 1.85s |
| sagasu リポジトリ自身(`--read-magic`) | 64 | 100.0% | 100.0% | 93.8% | 6.2% | 0.01s |

「構造タグ以外」= `format:` / `ext:` / `kind:` / `path:` を除いた名前空間
(`date:` / `version:` / `pattern:` / `anomaly:` / ユーザー定義)を 1 つ以上持つ割合。

前者は拡張子とディレクトリがあれば必ず付くので、それだけを引用すると
「絶対に失敗しない計測」になる。だから両方を報告する。

**この 2.1% は低いのではなく、コーパスの性質そのもの。** `/usr` も
ソースツリーも機械が生成・配置した木であって、`2024-03_請求書_v2.xlsx` のような
人間の命名規則はほとんど存在しない。日付・版数・命名パターンの各名前空間は
人が整理した文書ツリーで効く軸なので、上の数字は**下限**として読むべきもの。
その種のコーパスでの実測は M4(実機のドキュメントツリー)で取る。

なお `/usr` の 63,901 ファイルに対する `anomaly:format-mismatch` は 7 件で、
その全件が実際に矛盾していた(GNU ld のリンカスクリプトなのに `.so`、
先頭にプレフィクスが付いた `.zip`)。誤検出は 0 件。

### 4-1. この計測で潰した誤検出

同じ実測で `version:` / `pattern:` の生成規則の緩さが3件見つかったので、
規則を狭めた(いずれも単体テストで固定してある):

| 元の規則 | 誤検出した実例 | 修正後 |
|---|---|---|
| トークン `copy` | `copy.bc` `geqo_copy.bc` `COPY.7`(PostgreSQL の COPY 文) | 接尾辞 `- Copy` / `のコピー` / 末尾の `(N)` のみ |
| 接尾辞 `-copy` | `edit-copy.svg` `folder-copy.svg`(アイコン名) | 空白付きの `- copy` のみ |
| 部分文字列 `backup` | `pg_basebackup` `dpkg-db-backup.service` `Backup.pm` | 拡張子(`.bak` 等)と末尾 `~` のみ |
| 前方一致 `screenshot` | `screenshotannotationdialog.ui`(LibreOffice の UI 定義) | 前方一致の直後が区切り文字・数字・終端であること |

`report_backup.xlsx` のような「名前に backup を含むが拡張子は普通」のファイルは
**意図的に取りこぼす**。名前の中の "backup" は状態ではなく話題で、
そのファイルは `sagasu find backup` で引ける。件数が合わない名前空間より、
黙って無視されるようになる名前空間の方が高くつく。
